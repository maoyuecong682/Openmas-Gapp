# Q2 Revised Protocol: Dataset-Column Paired Ablation

## 1. Why the previous Q2 table was wrong

The previous table averaged several construction indicators on the same 20
cases. That answers “which structural metric is high?” but does not match the
intended ablation design. The revised result is a paired table: rows are
pipeline variants, columns are independent datasets/tracks, and each column
has exactly one primary metric. Every ablation is compared with Full Graph
Harness on the same examples and seeds.

## 2. What data we currently have

There are two different data layers and they must not be conflated:

### Construction suite

The frozen 20-case suite is an expert-authored application-construction set:

- 8 development cases and 12 validation cases;
- 4 structural families: sequential, multi-branch, feedback-driven and constraint-heavy;
- domains: finance, biomedical, software, plus science/legal proxy cases;
- each case has a requirement, task graph, capability contracts, forbidden components, constraints, trace contracts and three execution tasks.

These cases are not standard QA datasets. They are the application-construction evaluation set.

### Underlying task datasets

The three execution sources currently present in `cleaned/` are:

| Dataset | File | Intended primary metric |
|---|---|---|
| FinQA | `cleaned/finance_tasks.jsonl` | runtime-gated answer/task success |
| PubMedQA | `cleaned/biomedical_tasks.jsonl` | runtime-gated answer/task success |
| SWE-bench Verified | `cleaned/software_tasks.jsonl` | patch/trace success proxy until a real patch executor is connected |

The current Q2 formal run used `MinimalMARRuntime` without a domain task
adapter, so its execution rows do not contain real answer accuracy. Therefore
FinQA/PubMedQA columns produced from that file are structural runtime proxies,
not QA accuracy results. A final Q2 table must rerun with the domain adapter
enabled if answer accuracy is claimed.

## 3. Revised table columns

The primary table is generated by `openmas_bench/q2_dataset_eval.py` and has one
metric per column:

| Column | Primary metric | What it tests |
|---|---|---|
| FinQA | task success = answer correctness × runtime validity × trace validity | whether the constructed application completes financial QA while respecting its runtime contract |
| PubMedQA | task success = answer correctness × runtime validity × trace validity | biomedical QA under the generated application workflow |
| SWE-bench | trace/patch proxy | whether the generated repair workflow executes valid patch-related steps |
| Requirement Alignment | strict requirement alignment | task, capability, constraint and forbidden-component alignment |
| Workflow Structure | strict path success | exact workflow relation and executable-path preservation |
| Blueprint Fidelity | strict Blueprint fidelity | Blueprint node/edge realization; `w/o Blueprint` receives zero |
| Governance | strict governance success | constraint-heavy cases only; constraint satisfaction gated by executable validity and forbidden-use absence |

The final paper may show the three domain columns in the main table and put the
three construction tracks in a companion table, or show all seven if space allows.

## 4. Paired comparison

For each cell, report:

```text
variant mean ± std
delta_vs_full = variant mean - Full Graph Harness mean
```

The Full row is not used as a normalization denominator. It is an actual
experimental condition. A negative delta means removing the module harmed the
dataset's primary metric.

## 5. Strict evaluation changes

The revised evaluator no longer calls declaration recall “satisfaction”. It
uses explicit names:

- `strict_requirement_alignment`;
- `strict_path_success`;
- `strict_blueprint_fidelity`;
- `strict_governance_success`.

These are still conservative proxies when computed from old serialized rows.
The next runtime revision must add task-local capability binding, exact edge
execution, constraint-before-decision checks, artifact provenance and answer
correctness. Set-based existence alone is insufficient.

## 7. Required final rerun

1. Keep the same construction cases, variants, model, budget and seeds.
2. Enable the domain task adapter for FinQA and PubMedQA.
3. Use the patch/trace adapter for SWE-bench.
4. Compute one primary metric per dataset column.
5. Report mean/std and paired delta against Full.
6. Keep structural diagnostics in an appendix, not inside the primary dataset score.
